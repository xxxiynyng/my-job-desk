## 1. 기획 SSOT 변경안 (`38b01b3f87138145a89ec4d1fa3706be`)

### 1-1. §3 데이터 모델 — `3-3. 소재(Story) 계층` 신설

> 탭2는 **활동(Activity = 기존 Item)** 과 그 아래 **소재(Story)** 두 계층으로 구성된다. 13개 프리셋은 활동 계층 그대로이며 대체되지 않는다.
> 활동 = "무엇을 했나"(공모전 참가, 인턴 근무) · 소재 = "그 안에서 자소서에 쓸 한 장면"(갈등 조율, 지표 개선). 활동 1개에 소재 N개.

**Story 필드** (코드 정본: `src/features/experiences/story/model.ts`)

| 필드 | 내용 |
|------|------|
| `activityId` | 부모 활동 — 소재는 반드시 활동에 속한다 |
| `headline` / `body` | 소재 제목 / 본문 |
| `rawExcerpt` | **원문 발췌 원본** — 근거 검증·재분석·감사용 |
| `starHint` | STAR 4구간(situation·task·action·result) **발췌** — 생성하지 않는다 |
| `starHintStale` | 본문이 바뀌어 발췌가 낡았음 |
| `resultMetric` | 결과 수치 |
| `status` | `ai_draft` / `user_confirmed` — 확인 전까지 커버리지에 안 센다 |
| `origin` | `ai` / `manual` / `split` |
| `insufficient` | 승격 최소조건 미달 |
| `competencies` | NCS 역량 태그 배열(아래) |
| `deletedAt` | 소프트삭제 — 기존 휴지통 규약과 동일 |

**StoryCompetency (역량 태그)**: `competency`(NCS 10축) · `subCompetency`(하위능력) · `evidenceText`(**근거 문장 — 반드시 `rawExcerpt`의 부분 문자열**) · `confidence`(high/low) · `userVerdict`(unset/accepted/rejected) · `taggedBy`(ai/user).

**NCS 10축**: 의사소통 · 수리 · 문제해결 · 자기개발 · 자원관리 · 대인관계 · 정보 · 기술 · 조직이해 · 직업윤리. **발명·변형하지 않는다**(국가 표준 분류). 하위능력 rubric은 `model.ts`의 `NCS_SUB`가 정본.

**저장**: `pickd.stories.v1` (localStorage). 읽기 경로는 `story/store.ts` 단일 — 컴포넌트가 localStorage를 직접 읽지 않는다.

### 1-2. §4-3 전면 개정 — 구 B-1/B-2 모듈표 폐기

**폐기할 것**

**신설할 것 — AI 경로 3종**

| 경로 | 시점 | 하는 일 | 코드 |
|------|------|---------|------|
| **인터뷰** | 사용자가 시작 (동기, 수 초) | 최대 3턴 대화 → 활동·소재 초안 | `nextInterviewTurn` · `buildInterviewDraft` |

| **태깅** | 소재 생성·수정 시 | 본문 → NCS 역량 태그(근거 문장 동반) | `tagCompetencies` |

**충분성 판정 (구 5축 자리)**
- `checkSufficient(text)` → 소재 승격 최소조건. 미달이면 `insufficient: true`로 두되 **버리지 않고** "조금 더 채우면 소재가 되는 것 N개"로 확인 화면에 따로 모아 보여준다.
- `extractStarHint(body)` → 본문에서 STAR 4구간을 **발췌**한다. 없는 구간은 빈 값. **생성 금지.**

**불변 원칙 (§4-7에 추가)**
1. 근거 문장(`evidenceText`)은 반드시 **`rawExcerpt`(사용자 원문)의 부분 문자열**이어야 한다 — AI가 근거를 지어내지 못하게 하는 구조적 장치. AI 생성 문장(`body`) 기준이 아니다.
2. `rawExcerpt` 원본은 항상 보존한다 — 재분석·감사 경로.
3. **AI는 문장을 만들되 구체 사실은 빈칸으로 남긴다** — 상세는 §1-7. (구 원칙 "문장을 만들어 주지 않는다"는 2026-07-29 폐기)
4. 활동·소재는 사용자가 **저장을 눌러야** 실제로 만들어진다. (등록 경로는 확인 화면, `activity` 모드는 패널 내 저장 버튼 — §3-3)

### 1-7. §4-7 개정 — "생성 금지" → "사실은 사용자가 넣는다" (확정)

**구 원칙 폐기.** 기존 `writingAids.ts` 원칙 ③("완성된 문장을 넣어주지 않는다")과, 그 전제 위에 세웠던 소재/본문 경계는 폐기한다. 인터뷰에서도 **입력 보조 단계·답변 후 다듬기 단계 모두 AI가 문장을 만든다**(2026-07-29 확정).

**신 원칙: AI가 문장을 만들되, 사실은 사용자가 넣는다.**

구 원칙이 막으려던 위험은 여전히 실재한다 — 완성 문장을 주면 사용자가 그대로 제출하고, **실제로 안 한 일이 경험 자산으로 굳는다.** 그래서 "문장을 주지 않는다"를 "**빈칸을 남긴 문장을 준다**"로 바꾼다. 금지 대신 구조로 막는 방식이다.

| 장치 | 내용 |
|------|------|
| **빈칸 강제** | 생성 문장의 구체 사실(수치·기관명·기간·인원·역할)은 `BLANK`(`__`)로 비워 둔다. 예: `"엑셀 양식을 만들어 정산 기간을 __주에서 __일로 줄였어요"`. 빈칸이 남아 있으면 그대로 제출해도 자기 사실을 채울 수밖에 없다 |
| **원답변 보존** | `rawExcerpt` = 사용자가 실제로 입력한 원답변. `body` = 다듬은 문장. **덮어쓰지 않는다** — "내가 실제로 뭐라고 말했는가"의 추적 경로 |
| **근거는 원답변 기준** | 역량 태깅(`tagCompetencies`)·STAR 발췌(`extractStarHint`)는 **`rawExcerpt`를 본다**. AI가 만든 문장에서 근거를 뽑으면 AI가 AI를 인용하는 순환이 된다 |
| **반영은 사용자 손으로** | 생성 문장은 자동 저장되지 않는다. "소재로 저장" 또는 "본문에 넣기"를 눌러야 들어간다 |

기존 말머리·낱말(`AIDS_*`)은 **그대로 유지**한다 — 예시 문장과 용도가 다르다(조각 삽입 vs 문장 채택). 둘 다 제공한다.

## 3. 신규 기획 — 인터뷰 사이드 패널 (결정 2번 구체화)

> **요구**: 등록은 인터뷰 모드로. 편집형 문서 구조(경험 상세)에서 버튼을 누르면 **같은 인터뷰가 기존 사이드 패널 자리에** 뜬다.

### 3-1. ⚠️ 먼저 고쳐야 할 결함 — 지금 배선은 새 활동을 만든다

`ExperiencesPage.tsx:1483`이 이렇게 배선돼 있다:

```
onRequestInterview={() => flow.openInterview("cold_start")}
```

그래서 **경험 A의 상세를 열고 인터뷰를 시작하면**, 1턴에서 활동 유형 칩을 다시 고르고 → 확인 화면 저장 시 `saveReview()`가 `createActivity()`를 호출해 **별개의 새 활동 B가 생긴다.** 원래 보던 경험 A에는 소재가 붙지 않는다. 사용자가 기대하는 동작과 반대다.

즉 이번 재설계는 UI 이동이 아니라 **흐름 결함 수정을 포함**한다.

### 3-2. 두 표면, 하나의 엔진

| | 표면 1 — 등록 | 표면 2 — 보강 (신규) |
|---|---|---|
| 진입 | 탭2 상단 `경험 추가` / 커버리지 갭 카드 | 경험 상세의 ✦ 버튼, 소재 0건일 때의 `StoryEmpty` |
| 셸 | `Dialog` 720px 모달 | **오른쪽 320px 사이드 패널** (구 AI 패널 자리) |
| 모드 | `cold_start` · `gap` | **`activity` (신설)** |
| 1턴 | 활동 유형 칩 선택 | **건너뛴다** — 활동이 이미 정해져 있다 |
| 턴 수 | 최대 3 | **최대 2** (1턴 스킵분만큼 감소) |
| 완료 후 | 확인 화면 → 저장 시 **활동 생성** | 확인 화면 **생략**, 소재만 현재 `item.id`에 즉시 추가 |
| 결과 목적지 | 소재 (활동과 함께) | **소재 / 본문 중 선택** (§3-5) |

**구현 방향**: `InterviewMode.tsx`에서 **대화 로직과 셸(Dialog)을 분리**한다. 상태(bubbles·turn·answers·picked)는 이미 컴포넌트 내부에 모여 있어 셸만 교체하면 재사용 가능하다.

- `InterviewCore` — 대화 흐름 전부(현 `InterviewMode` 내용물)
- `InterviewDialog` — 기존 720px 모달 셸 (표면 1)
- `InterviewPanel` — 320px 사이드 패널 셸 (표면 2)

### 3-3. `activity` 모드 동작

1. **1턴 스킵**: 활동 유형은 `item.type`(narrative 8종 중 하나)에서 가져온다. `entryOptions.NarrativeType`이 프리셋 8종을 그대로 덮으므로 매핑이 이미 존재한다.
2. **첫 질문은 장면을 묻는다**: "이 활동에서 가장 기억에 남는 순간은요?" — 활동 자체가 아니라 그 안의 **한 장면**을 끌어내야 소재가 된다.
3. **본문 참조**: `item.document`가 이미 있으면 질문에 반영한다(같은 얘기를 다시 묻지 않게). 없으면 백지 기준.
4. **완료 시 — 확인 화면을 생략한다**(2026-07-29 확정). `buildInterviewDraft`가 돌려준 `primary.story`의 `activityId`를 **현재 `item.id`로 덮어쓰고** 바로 `upsertStories`. `createActivity`를 호출하지 않는다. `extras`(함께 고른 활동)는 이 모드에서 **수집하지 않는다**.
   - 근거: 이미 보고 있던 경험에 소재만 붙이는 것이라 확인할 대상이 적고, 320px 패널에서 풀 화면 모달(`ExtractReview`)이 뜨면 맥락이 끊긴다.
   - 안전장치: 추가된 소재는 바로 아래 `StoryCard`로 보이고 카드에서 수정·삭제(휴지통 14일)가 가능하다. 즉 "확인 후 저장" 대신 "저장 후 즉시 보이고 되돌릴 수 있음"으로 대체한다.
5. **토스트**: "소재 N개를 추가했어요" (기존 `StorySection` 문구와 통일)

### 3-4. 레이아웃

- 폭 320px, `grid-cols-[1fr_320px]` — 구 AI 패널 그리드 전환을 그대로 재사용
- 헤더: 아이콘 + "인터뷰" + 부제(모드별 한 줄) + 닫기 X
- 본문: 대화 스크롤 영역(`aria-live="polite"` 유지)
- 하단: 칩 턴이면 칩 목록, 서술 턴이면 textarea + `writingAids`(말머리·낱말·단위)

- 진행 표시는 텍스트만("3개 중 2번째") — 진행 바 금지(디자인 §0-10)

### 3-5. 패널은 하나 — 끝에서 목적지를 고른다 (확정)

인터뷰가 문장 생성까지 하므로(§1-7) 문장 다듬기 패널과 흐름이 **질문 → 답변 → 문장**으로 동일해졌다. 둘을 **하나로 합친다**(2026-07-29 확정). 차이는 결과가 어디로 가느냐뿐이고, 그건 **마지막에 버튼으로 고르게** 한다.

```

   질문 → 답변(말머리·낱말·예시 문장 보조) → 생성 문장
```

- **두 버튼의 문구**: "소재로 저장"(자소서에 꺼내 쓸 한 장면으로) / "본문에 넣기"(활동 설명에 이어 붙이기). 무엇이 달라지는지 부제 한 줄로 밝힌다.
